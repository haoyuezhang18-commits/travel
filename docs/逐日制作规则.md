# 逐日详细行程制作规则

通用规则在 [`铁律.md`](铁律.md)（时间、变量、内容、口吻、格式、核对、优先级）。**这一页只讲逐日制作这个动作本身**，不重复铁律里的条目。

## 一、开始当天前，先锁定这九项

- 日期和星期
- 当天人数；儿童写年龄
- 出发地点与住宿地点
- 固定航班、火车、演出、预约时间
- 交通方式，以及是否取车／还车
- 客户必去、可选、不去的景点
- 前几天已经去过的景点
- 客户希望的出发时间和节奏
- 当天在哪座城市 → 对应哪一页城市页、哪条编号路线

## 二、怎么选路线

1. 打开 [英国索引](../catalog/英国城市模板索引.md) 或 [欧洲索引](../catalog/欧洲城市模板索引.md) 的跳转表 → 进城市页。
2. 城市页开头有"这几件事决定用哪条路线"，先回答那几个问题。
3. 选定编号路线（如 `LON-R01-A`、`ROM-R02`）。
4. **只用一版，不要跨版本拼接。** 同一批景点在多个版本里被排过不同顺序，混用会自相矛盾。
5. 看该页末尾的 **"改这天要动哪几行"** 表，对照客户变量确定要改哪些行。
6. 真正填内容时，**按编号只取那一张表**，不要通读整份 DOCX：

```bash
python3 tools/取路线.py LAK-R03
```

7. 出交付文档时，**用 `tools/拼行程.py` 把表连图搬过去，不要重打内容**：

```bash
python3 tools/拼行程.py 配方.json 输出.docx
```

配方里每天写清 `编号` 和 `替换`（变量对照表），脚本会保留图片、字体、列宽和 `●` 分点。**重打一遍等于把模板攒下来的图片和排版全丢掉。**

也可以在 WPS 里 Ctrl+F 搜编号——每张表前面都有 `【LAK-R03】…` 标题行，多版本文件顶部还有一张本文件路线索引。编号到文件的对照表在 [`catalog/路线定位表.csv`](../catalog/路线定位表.csv)。

## 三、模板使用原则

1. 以城市模板的成熟路线顺序为基础。
2. 初步框架只提供景点范围，不强制早中晚顺序。
3. 先解决开放时间，再调整动线。
4. 只删除与新客户明确无关的内容。
5. 交通方式变化时，**只替换交通相关内容**，不重写整个城市模板。
6. 模板首尾常常绑定了特定的上／下一城（如"佛罗伦萨→罗马"开头、"→威尼斯"结尾）。客户前后城市不同时，**这些绑定段整段删掉或重写**。欧洲索引里有完整的衔接关系表。

## 四、先看模板陷阱

《[模板陷阱](模板陷阱.md)》记了九条真出过错的坑，其中三条最容易翻车：

1. **多天套装**：8 个模板文件内部分了"几天"的节，客户住几天就用对应那套，不要拿一天版拆两天。
2. **选版本**：先按内容筛，再挑图片最多的那版（`取路线.py --list` 直接显示图片数）。
3. **转场版残留**：模板常是"某城最后一天＋转场下一城"的合体，当天不转场就要把后半段整段删掉。

## 五、模板本身可能是错的

模板是可复用素材，**不是默认正确的事实**。已知有缺陷的模板都记在对应城市页的"已知问题"里（约克晚间时间轴、坎特伯雷四处硬伤、湖区跨城交通被拆行等）。

调用前先看一眼城市页有没有标问题；照抄一个坏的时间轴，客户会直接扑空。

## 六、每天做完就查

按《[质检清单](质检清单.md)》的 8 类错误过一遍，再进入下一天。**不要攒到最后一起查。**
