# 框架匹配规则：找匹配度最高的一条，改动最小

生成初步框架时，**默认动作不是"写一个新框架"，而是"从模板库里挑出最接近的一条，然后只改必须改的"**。

改得越少，出错越少、越快，模板里那些踩过坑才攒下来的细节（停车点、机位、末班车、避坑提示）也才保得住。

## 一、先算匹配度，再动手

对每个待安排的城市，按下面五项打分，**选总分最高的那条编号路线**：

| 项 | 权重 | 说明 |
|---|---|---|
| **来向／去向** | 最高 | 客户从哪个城市来、去哪个城市。模板首尾常绑定特定城市，对上就省掉整段重写 |
| **交通方式** | 高 | 自驾／火车／包车。这项不对，全天的停车、班次、耗时都要重写 |
| **停留时长** | 高 | 半日／一日／两日。选错会导致强行塞或强行删 |
| **抵达时间** | 中 | 清晨／上午／下午／夜车。决定当天能不能排入内项目 |
| **同行结构** | 中 | 带老人小孩／体力好／赶时间。决定徒步和登高项目留不留 |

**打平时的取舍**：优先选**版本更完整、备注更细**的那一条（例如卡普里选 `SOR-R05` 双方案版、阿马尔菲选 `SOR-R02-B` 详版），细节可以删，删掉容易、补回来难。

## 二、匹配度分三档，对应三种改法

### 完全复用（改 3 行以内）

城市、景点组合、交通方式、停留时长基本一致。

**只改**：日期与星期、人数与儿童年龄、酒店名称与区域、固定班次时刻。

**不动**：景点顺序、时长分配、所有 `●` 备注。

### 部分复用（改首尾 + 少数几行）

城市相同，但来向、交通方式、抵达时间或某几个景点不同。

按城市页末尾的 **"改这天要动哪几行"** 表逐条对照——那张表就是为这种情况写的。典型改法：

- 来向不同 → 删掉模板开头绑定的跨城段，整天时刻前移或后移
- 交通方式变了 → **只替换交通相关的行**，景点内容和备注保持不动
- 加一个景点 → 同时决定砍掉或缩短哪个，不要无限叠加
- 减一个景点 → 空出的时间明确给谁，不要留白

### 无模板（才从零写）

本地确实没有对应城市或组合时才新写，并**标记"新增内容"**。

新写之前先确认三件事：

1. 是不是真的没有？先用 `python3 tools/取路线.py --list 关键词` 搜一遍。
2. 有没有邻近城市的模板可以借结构（例如小镇一日游的骨架是通用的）。
3. `欧洲城市汇总版本.docx` 里有没有——那份文件覆盖了模板库缺的一批城市（马德里、塞维利亚、格拉纳达、赫罗纳、阿姆斯特丹、根特、诺丁汉、圣米歇尔山）。

## 三、框架阶段要输出什么

给负责人的框架里，每一天都标清楚这三样，方便你一眼看出哪天要花时间：

```text
Day 3｜9/26（周四）伦敦
路线：LON-R02-A（大英博物馆＋国家美术馆｜含早茶版）
匹配度：完全复用
要改：日期、2大1小(7岁)、酒店改住国王十字
```

```text
Day 6｜9/29（周日）剑桥当日往返
路线：LDT-R02（剑桥宽松版）
匹配度：部分复用
要改：① 周日菲茨威廉博物馆闭馆 → 换国王学院
      ② 客户住帕丁顿 → 开头改成 Circle 线到 King's Cross
      ③ 晚上有音乐剧 → 换 LDT-R03 紧凑版，提前1小时回城
```

## 四、这几种情况不要硬套模板

- 客户的**硬约束**（预约时段、固定班次、闭馆日）与模板顺序冲突时，**硬约束赢**，重排模板。
- 客户明确说了顺序，按客户的来。
- 模板本身被标了"已知问题"（约克晚间时段、坎特伯雷时间轴、威尼斯 R03 结构）时，只借景点顺序，时间轴重算。
- 一天塞两个大项目（如少女峰＋First、卢浮宫＋凡尔赛）时，先问负责人客户体力，不要默认能塞下。

## 五、一句话总结

**先搜、再挑、后改；能不动的一律不动。** 模板里每一条看似啰嗦的备注，都是某一单踩过的坑。
